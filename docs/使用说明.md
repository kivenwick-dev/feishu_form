# 飞书报销表归档工具使用说明

本工具把飞书电子表格中的员工信息、PDF/普通附件，与本地 Excel 中的浮动图片合并，按员工生成文件夹并打包 ZIP。

工具只读取飞书数据，不会修改、删除、上传或分享线上表格。

## 一、开始前必须确认

线上飞书表格和本地 Excel 必须是同一张报销表的对应版本。线上链接负责读取表格和普通附件，本地 Excel 负责补充浮动图片；两者不是两份可以随意拼接的表。

请在运行前确认：

1. 线上链接和本地 Excel 属于同一个报销表、同一个月份/批次。
2. 两份表包含同一批员工，员工姓名能够一一对应。
3. Excel 中用于补图的工作表是第一个工作表。程序目前固定读取 Excel 的第一个工作表。
4. 员工姓名列、附件列的表头没有被改名或错位。
5. 最好保持两份表的员工顺序、表头行和列顺序一致。尤其不要只给 Excel 增删员工、插入整列或重新排序后再混用。
6. 不要把另一张表、另一批次或另一个部门的 Excel 作为补图文件。

如果两份表无法一一对应，程序可能会把图片放到错误的员工目录，或者输出“无法匹配员工行或列”“表头未识别为附件列”。程序不会根据图片在画面上的视觉重叠位置猜测图片归属。

## 二、从 GitLab 拉取项目

推荐使用 SSH：

```bash
git clone git@git.liberai.work:ldp/feishu-archiver.git
cd feishu-archiver
```

如果使用 HTTPS：

```bash
git clone https://git.liberai.work/ldp/feishu-archiver.git
cd feishu-archiver
```

确认已经安装 Go，并且版本满足项目 `go.mod` 中声明的版本：

```bash
go version
go mod download
```

请始终在项目根目录运行命令，也就是能够看到 `go.mod`、`cmd/` 和 `docs/` 的目录。

### 打包与分发（单文件、内置凭据）

在项目根目录用一条命令即可生成 Windows / macOS / Ubuntu 三个系统、共四个平台的单文件程序（凭据在构建时注入）：

```bash
FEISHU_APP_ID='cli_xxx' FEISHU_APP_SECRET='xxx' go run ./cmd/build
```

产物位于 `dist/`：

- `dist/windows-amd64/feishu-web.exe`
- `dist/darwin-arm64/feishu-web`（Apple 芯片）
- `dist/darwin-amd64/feishu-web`（Intel 芯片）
- `dist/linux-amd64/feishu-web`

同事拿到对应文件后无需任何配置：

- Windows：双击 `feishu-web.exe`；
- macOS：首次运行执行 `chmod +x feishu-web`，若被拦截则执行 `xattr -dr com.apple.quarantine feishu-web` 后再打开；
- Ubuntu：`chmod +x feishu-web && ./feishu-web`（目录选择需要系统已安装 zenity，否则手动填写输出路径）。

内置凭据可用环境变量或 `--app-id` / `--app-secret` 覆盖。注意：二进制内的凭据只做了轻量混淆，可被逆向提取，仅适用于内部可信分发。

### Windows 启动入口

项目根目录下的 `windows/` 已提供 Windows 启动和打包入口：

- 双击 `windows/start.bat` 或 `windows/feishu-web.exe` 即可启动本地网页；打包后的程序已内置飞书凭据，无需配置；
- 运行 `windows/build.ps1` 会调用 `go run ./cmd/build -targets windows/amd64`，生成 `dist/windows-amd64/feishu-web.exe`，并复制一份到 `windows/feishu-web.exe` 方便双击；
- 详细说明见 [`windows/README.md`](../windows/README.md)。

## 三、配置飞书应用凭据

程序需要企业自建飞书应用的：

- `FEISHU_APP_ID`
- `FEISHU_APP_SECRET`

飞书应用需要具备表格归档所需的只读能力，包括：

- Wiki/云文档节点读取权限；
- 电子表格读取权限；
- 云盘/Drive 文件和媒体下载权限。

同时，当前登录的飞书租户和应用必须能够访问目标表格。不要把 App Secret 写入代码、提交到 Git、截图或发送到聊天中。

### 命令行环境变量方式（备用）

如果不使用 macOS 钥匙串，也可以在当前终端中配置环境变量。环境变量只对当前命令或终端会话生效，不会写入项目文件：

```bash
export FEISHU_APP_ID='cli_xxxxxxxxxxxxx'
export FEISHU_APP_SECRET='xxxxxxxxxxxxxxxx'
```

检查变量是否存在时不要直接打印 Secret：

```bash
test -n "$FEISHU_APP_ID" && echo "FEISHU_APP_ID 已设置"
test -n "$FEISHU_APP_SECRET" && echo "FEISHU_APP_SECRET 已设置"
```

如需清除当前终端中的变量：

```bash
unset FEISHU_APP_ID FEISHU_APP_SECRET
```

### 推荐：macOS 钥匙串和双击启动方式

推荐把凭据保存到 macOS 钥匙串。项目根目录的 `启动线上归档工具.command` 会从钥匙串读取凭据，之后可以直接双击启动，不需要每次重新输入环境变量：

- 服务名：`reimbursement-feishu-app-id`
- 服务名：`reimbursement-feishu-app-secret`
- 账户：当前 macOS 用户名

第一次使用前，可以将凭据写入钥匙串：

```bash
security add-generic-password -a "$USER" -s reimbursement-feishu-app-id -w 'cli_xxxxxxxxxxxxx' -U
security add-generic-password -a "$USER" -s reimbursement-feishu-app-secret -w 'xxxxxxxxxxxxxxxx' -U
```

启动脚本会自动使用它所在的项目目录，因此仓库可以放在任意路径。首次使用时请确保脚本具有执行权限，然后双击该文件，或在终端运行：

```bash
chmod +x "启动线上归档工具.command"
./启动线上归档工具.command
```

服务默认打开：

```text
http://127.0.0.1:8765
```

页面只监听本机，不会对局域网开放。要禁止自动打开浏览器，可以使用：

```bash
NO_BROWSER_OPEN=1 go run ./cmd/feishu-web
```

## 四、网页归档流程

1. 启动 `启动线上归档工具.command`。
2. 在“飞书表格链接”中粘贴目标 Wiki/电子表格链接。
3. 在“本地 Excel 文件”中选择与线上链接一一对应的 `.xlsx` 或 `.xlsm` 文件。
4. 在“输出目录”中选择归档保存位置，默认是项目下的 `outputs`。
5. 点击“开始归档”。
6. 等待日志显示完成，再到输出目录检查 ZIP 和员工文件夹。

飞书链接应是 `https://...feishu.cn/wiki/...` 格式。链接可以带 `?sheet=...` 指定工作表；不带 `sheet` 时，程序会使用飞书返回的第一个工作表。

网页中的“文件抽屉”可以打开 `docs/` 目录中的说明文件。如果刚更新了代码或说明文档，必须退出旧的本地服务并重新启动，再在浏览器执行强制刷新。

## 五、命令行方式

### 只检查链接和权限

```bash
FEISHU_APP_ID='cli_xxxxxxxxxxxxx' \
FEISHU_APP_SECRET='xxxxxxxxxxxxxxxx' \
go run ./cmd/feishu-probe \
  --url 'https://example.feishu.cn/wiki/xxxxxxxxxxxxxxxx'
```

结果默认写入：

```text
outputs/feishu_probe_result.json
```

### 执行完整归档

```bash
FEISHU_APP_ID='cli_xxxxxxxxxxxxx' \
FEISHU_APP_SECRET='xxxxxxxxxxxxxxxx' \
go run ./cmd/feishu-probe \
  --archive \
  --archive-dir outputs \
  --url 'https://example.feishu.cn/wiki/xxxxxxxxxxxxxxxx?sheet=xxxxxx' \
  --excel '/Users/你的用户名/Documents/同一张报销表.xlsx'
```

常用参数：

| 参数 | 作用 |
| --- | --- |
| `--url` | 飞书 Wiki/电子表格链接，必填 |
| `--excel` | 本地 Excel 路径，用于补充浮动图片 |
| `--archive` | 开启批量归档 |
| `--archive-dir` | 输出目录，默认 `outputs` |
| `--output` | 探测结果 JSON 路径 |
| `--app-id` | 直接传入 App ID，可替代环境变量 |
| `--app-secret` | 直接传入 App Secret，可替代环境变量，不建议写入 shell 历史 |

## 六、线上链接和本地 Excel 如何对应

### 1. 员工对应

程序先从线上表格建立员工目录，再读取 Excel 中“员工姓名”或“姓名”列，把浮动图片放进同名员工目录。因此两份表中的员工姓名必须一致。

同名员工会生成类似 `张三`、`张三_2` 的目录。为了避免同名导致顺序歧义，建议员工姓名在本批次内唯一，并保持两份表的顺序一致。

### 2. 工作表对应

本地 Excel 补图固定读取第一个工作表。请把与飞书链接对应的工作表放在 Excel 的第一个标签页；不要把“汇总”“说明”或其他月份放在第一张。

### 3. 附件列对应

浮动图片按照图片的实际锚点列归类，不按照图片在画面上覆盖到的区域归类。

可识别的列名包括：

- 含“发票”的列 -> `发票`
- 含“支付”“充值成功”“付款”的列 -> `支付_账号充值成功截图`
- 含“会员开通”“开通截图”“续费”的列 -> `会员开通截图`

例如图片看起来覆盖了 N 列，但它的实际锚点是 P 列，那么程序会按 P 列处理；如果 P 列不是上述附件列，图片会被跳过。这是为了避免把左侧或相邻表头下的图片误归到当前单元格。

### 4. 一个单元格有多张图片

同一个单元格可以有两张、三张甚至更多浮动图片，程序会逐张读取。相同图片内容如果已存在于对应员工目录，会按重复图片跳过；日志中的“图片统计（文件夹实际数量）”统计的是最终文件夹里实际存在的文件数量。

## 七、输出结果

完成后，输出目录通常包含：

```text
<源表名称>/
├── <员工姓名>/
│   ├── 报销信息.txt
│   ├── 发票/
│   ├── 支付_账号充值成功截图/
│   └── 会员开通截图/
├── 汇总.txt
└── 失败清单.txt        # 只有存在下载失败时才生成

<源表名称>.zip
feishu_probe_result.json
```

说明：

- `报销信息.txt` 保存员工的非附件字段；
- `发票`、`支付_账号充值成功截图`、`会员开通截图` 保存线上附件和 Excel 浮动图片；
- `汇总.txt` 保存员工人数、报销金额总和和 90% 实际报销金额总和；
- `失败清单.txt` 记录无法下载的线上附件，不代表整批任务全部失败；
- 如果同名输出目录已经存在，程序会创建 `<源表名称>_副本1`、`<源表名称>_副本2`，不会覆盖旧结果。

完成后建议至少抽查三名员工：

1. `报销信息.txt` 的姓名、金额和部门是否正确；
2. 发票、支付截图、会员截图是否归入正确目录；
3. Excel 中每个员工的浮动图片数量是否与日志中的“文件夹实际数量”一致；
4. 打开 ZIP，确认 ZIP 内部路径与员工文件夹一致。

## 八、常见问题

### 提示“请提供 --url，并通过 FEISHU_APP_ID / FEISHU_APP_SECRET...”

说明链接或应用凭据没有传入。检查：

```bash
test -n "$FEISHU_APP_ID" && echo ok
test -n "$FEISHU_APP_SECRET" && echo ok
```

网页启动方式请检查钥匙串中两个服务名是否正确。

### 提示“获取访问令牌失败”或飞书 API 权限错误

检查 App ID、App Secret 是否属于同一个企业自建应用，应用是否已启用，并确认应用具有 Wiki、Sheets、Drive/媒体只读和下载权限。还要确认目标表格对该应用所在租户可访问。

### 提示“未找到员工姓名表头”

程序只会识别“员工姓名”“姓名”“申请人”“报销人”“人员”等表头。请检查线上表格和 Excel 是否选择了正确的工作表，表头是否在实际数据上方且没有合并错位。

### 提示“无法匹配员工行或列”

通常表示本地 Excel 不是对应的那张表、员工姓名列错了、目标工作表不是第一个工作表，或表格中插入/删除了行列。请重新导出与线上链接同一版本的 Excel，并确认员工姓名和表头位置。

### 提示“表头未识别为附件列”

图片锚点所在列不是发票、支付或会员截图列。请检查图片的实际锚点单元格和该列表头，不要只看图片在 Excel 画面上的覆盖范围。

### 图片数量比文件夹显示的少

日志可能显示“跳过重复图片”。这表示图片内容已经存在，程序不会重复保存。最终统计以员工目录下对应文件夹的实际文件数量为准。

### 网页打不开或说明文档点击无响应

先关闭旧的 `feishu-web` 进程，再重新启动项目；如果浏览器缓存了旧页面，在 macOS 中按 `Command + Shift + R` 强制刷新。端口被占用时检查：

```bash
lsof -nP -iTCP:8765 -sTCP:LISTEN
```

## 九、安全注意事项

- 不要提交 `.env`、App Secret、钥匙串导出内容或包含敏感报销数据的 `outputs/`。
- 归档结果默认保存在本机，不会自动上传到 GitLab 或飞书。
- 使用共享电脑时，任务完成后清除环境变量，并妥善处理输出目录和 ZIP。
